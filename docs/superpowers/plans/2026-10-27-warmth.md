# Warmth Slider Implementation Plan

> **For agentic workers:** one task, TDD. Spec: `docs/superpowers/specs/2026-10-27-any-screen-design.md` (software screens); this plan adds warmth to them.

**Goal:** A per-screen "Warmth" slider (0–100) for software screens (DisplayLink etc.) that tints the existing overlay amber, approximating Night Shift where macOS's own Night Shift doesn't reach. Manual only.

**Why an approximation:** the window server composites windows with normal "over" blending, so an overlay can add colour but not remove blue. The tint is capped so it never becomes a heavy haze.

### Task W: Warmth

**Interfaces (produces):**
- `public struct OverlayColor: Equatable, Sendable { red, green, blue, alpha: Double }`.
- `public enum SoftwareDimming` gains `static let maximumWarmth = 0.35`, `static let amber = (red: 1.0, green: 0.6, blue: 0.2)`, and `static func overlay(level: Int, warmth: Int) -> OverlayColor?` — nil when no overlay is needed (level ≥ 100 and warmth ≤ 0). Model: a tint layer of amber at alpha `t = 0.35 × clamp(warmth)/100` under a black layer at alpha `d = opacity(level:)`, collapsed into ONE layer: `alpha = 1 − (1 − d)(1 − t)`; colour = `(1 − d) · t · amber / alpha` per channel (black contributes 0). Warmth clamps to 0…100 like levels.
- `SoftwareLevels` gains `func warmth(for key: String) -> Int` (default 0) and `mutating func setWarmth(_:for:)` (clamped). Decoding JSON saved before this change (no warmth field) must still work and yield warmth 0 everywhere.
- `SoftwareScreen` gains `warmth: Int`. `SoftwareBrightness` gains `func setWarmth(_ warmth: Int, for key: String)` (live overlay update, same debounced save as levels) and `@Published var warmthEnabled: Bool` persisted under UserDefaults key `"warmthEnabled"` (default true). When false, overlays are computed with warmth 0 (saved warmth values kept).
- Overlay panels use `backgroundColor = NSColor(srgbRed:green:blue:alpha: 1)` from the computed colour and `alphaValue = alpha`; created when `overlay(...)` is non-nil, removed when nil.
- Menu bar panel: under each software screen's brightness slider, when `warmthEnabled`, a "Warmth" slider row in the same style (0–100).
- Settings, in the section that covers keys/brightness or a new small "Other screens" section: `Toggle("Warmth sliders", isOn:)` with help text "Tints screens without hardware control amber, like Night Shift. Night Shift itself doesn’t reach DisplayLink screens."
- README: one short paragraph under the software-screens section.

## Revision: real colour temperature (2026-10-27)

Verified with Anh: `CGSetDisplayTransferByFormula` on the DisplayLink Philips screens visibly warms them. So warmth moves from the amber overlay (adds colour, ~28% blue cut) to the screens' colour tables (removes blue, like Night Shift). The overlay goes back to black, brightness only.

### Task W2: Warmth through colour tables

**Interfaces (produces), LGKit:**
- `public enum ColorTemperature`:
  - `static func kelvin(warmth: Int) -> Double` = `6500 − 38 × clamp(warmth)` (0 → 6500 K, 100 → 2700 K).
  - `static func multipliers(warmth: Int) -> (red: Double, green: Double, blue: Double)` — Tanner Helland black-body approximation (T = kelvin/100; for T ≤ 66: red 255, green `99.4708025861·ln(T) − 161.1195681661`, blue `T ≤ 19 ? 0 : 138.5177312231·ln(T − 10) − 305.0447927307`), each clamped 0…255, divided by the same function's value at 6500 K, then clamped to 0…1. Warmth 0 returns exactly (1, 1, 1).
  - `static func scaled(_ table: [Float], by factor: Double) -> [Float]` — every entry × factor.
- `SoftwareDimming.overlay(level:warmth:)`, `OverlayColor`, `maximumWarmth`, `amber` are removed; the overlay is plain black at `opacity(level:)` again (restore the pre-warmth overlay code path). `SoftwareLevels` warmth storage, `warmthEnabled`, the slider and the Settings toggle stay.

**App (`SoftwareBrightness` or a new `ColorTables.swift` it owns):**
- For each software screen's display ID, capture its base transfer table once per process (`CGGetDisplayTransferByTable`, capacity from `CGDisplayGammaTableCapacity`, fall back to 256) **before writing to it**, and keep it for the process lifetime (never recapture after writing — that would compound).
- Apply = `CGSetDisplayTransferByTable(id, n, red×r, green×g, blue×b)` from the base with `multipliers(warmth:)` (warmth 0 when `warmthEnabled` is false). Warmth 0 writes the base table back (exact restore). Never call `CGDisplayRestoreColorSyncSettings()` (it resets every display, including Night Shift on the others).
- Reapply on: `setWarmth`, `warmthEnabled` change, `rebuild()` (screen change, wake), and a 5 s timer that reads each warmed screen's current table and reapplies only if it differs from what was written (tolerance 1e-3 on the last entry of each channel). Timer runs only while some screen has effective warmth > 0.
- Only software screens are touched; the hardware screen and the built-in never.
- Settings help text: "Warms screens without hardware control, like Night Shift (which doesn’t reach DisplayLink screens). Quitting Screen Monitor puts their colours back."
- README paragraph updated to match (real colour temperature, not an overlay).
